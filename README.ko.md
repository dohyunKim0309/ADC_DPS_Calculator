# ADC DPS Calculator

*[English README](README.md)*

리그 오브 레전드 전투를 **이벤트 기반(event-driven)** 으로 시뮬레이션해서, 패치마다 원거리 딜러(ADC)의 아이템 빌드 순서를 DPS·골드 효율로 전수조사·랭킹하는 도구입니다.

op.gg, u.gg, lolalytics 같은 통계 사이트는 플레이어들이 *실제로* 뭘 사서 이기는지를 집계합니다. 이 프로젝트는 다른 질문에 답합니다: **수학적으로는 뭐가 강해야 하는가** — 메타가 굳기 전에, 검증 가능한 명시적 데미지 모델 위에서 계산합니다. 모델링된 모든 메커니즘은 다중 소스 교차검증된 패치 데이터로 구현하고, 검증 불가능한 가정은 코드에 가설(Hypothesis)로 명시합니다.

## 출력 예시 (패치 26.13, DDragon 데이터 16.13)

챔피언별 최적 4코어 빌드의 교차 비교(단일 대상, 지속딜 측정). 빌드는 1~4코어 4개 스파이크 전부에서 비교되며, 아래 발췌는 **3코어 시점** — 앞 3개 아이템 완성 기준 DPS/골드, 괄호는 각 빌드의 4번째 아이템:

```text
=== Cross-Champion Top1 Compare (1~4 Core) ===
[3 Core] Winner: Vayne (159.40 DPG)
  - Vayne  DPG 159.40 | DPS 1801.2 | Gold 11300 | 윤 탈 → 무한의 대검 → 도미닉 (4코어: 유령 무희)
  - CogMaw DPG 130.71 | DPS 1359.4 | Gold 10400 | 구인수 → 내셔의 이빨 → 황혼과 새벽 (4코어: 라바돈)
  - KaiSa  DPG 108.97 | DPS 1133.3 | Gold 10400 | 구인수 → 윤 탈 → 내셔의 이빨 (4코어: 터미너스)
  - Corki  DPG 104.14 | DPS 1187.2 | Gold 11400 | 윤 탈 → 무한의 대검 → 도미닉 (4코어: 정수 약탈자)
  - Ashe   DPG  92.63 | DPS  981.9 | Gold 10600 | 윤 탈 → C44 → 도미닉 (4코어: 무한의 대검)
  - Yunara DPG  91.61 | DPS  989.4 | Gold 10800 | 구인수 → 윤 탈 → 도미닉 (4코어: 무한의 대검)
  - Jinx   DPG  86.05 | DPS  912.2 | Gold 10600 | 윤 탈 → C44 → 도미닉 (4코어: 무한의 대검)
```

`DPG` = 1000골드당 DPS(골드 효율). (이즈리얼은 전용 시뮬은 있으나 교차 비교에는 아직 미연동.) 26.13에서 모델이 보여준 것들: 베인의 *이론상* 최적 빌드는 국룰 온힛(몰왕→구인수→터미너스)이 아니라 **풀 크리티컬**이었고, 코그모 최적은 AP 온힛 하이브리드, 애쉬와 징크스는 같은 크리 코어로 수렴. 물론 전부 모델의 한계를 상속합니다 — [모델 한계](#모델-한계-먼저-읽어주세요) 참조.

## 동작 원리

**이벤트 루프** (`adc_sim/engine.py`) — (다음 평타, 다음 스킬, 다음 상태 변화) 중 최소 시간만큼 시간을 진행. 동시 이벤트는 스킬을 평타보다 먼저 처리, eps 넛지로 동일 시각 고착 방지. 처치 시 오버킬 데미지를 이월하며 풀피로 리필 — 표준 측정은 **체력바 2개 처치**라 시작 버스트가 분산되고 현재체력 비례 효과(몰왕검)가 과대평가되지 않습니다.

**데미지 파이프라인** (`adc_sim/champion.py`) — 평타 치명타 기댓값 → 온힛 합산(구인수 2회 적용, 황혼과 새벽류 "온힛 1회 추가"는 가산으로 중첩) → 증폭(조건부 포함: Shadowflame은 타깃 HP 40% 이하만) → 방어력/마저 경감(곱연산 %관통 + 고정 관통, 고정 피해는 경감 우회). 챔피언 킷은 엔진 이벤트로 모델링: 베인 은화살 3타 고정 피해, 코그모 W 최대체력% 마법 온힛, 징크스 미니건 스택, 유나라 초월 로테이션 등.

**마나 = 하드 바운드 자원** — 시전은 현재 마나로 게이트, 틱마다 재생. 쿨이 돌아도 마나가 없으면 충전까지 대기. 무한 마나 가정 없음.

**랭킹 방법론** — 챔피언별 후보 풀에서 4아이템 구매 순서를 전수 열거(빌드당 %방관 아이템 1개 제한 같은 제약 포함). 각 빌드를 4개 파워 스파이크(1/2/3/4코어, 코어별 챔피언 레벨·타깃 스탯 고정)에서 **고정 컨트롤 빌드 대비 상대 골드 효율**로 채점 — 컨트롤은 챔피언별 국룰 메타 빌드(애쉬 크라켄→유령무희→무한→도미닉, 베인 몰왕→구인수→터미너스→유령무희 등)라 점수가 "메타 빌드 대비 골드 효율 %"로 읽힙니다. 초반 코어에 5:4:3:3 가중. 같은 4아이템 집합은 최고 순서 하나로 dedup. 시뮬 결과는 아이템 집합 단위로 메모이즈 — 전수조사가 가능한 이유입니다.

**케이스 기반 랭킹** (`case_ranking.py`) — 단일 랭킹을 넘어 28케이스 그리드(방어템 타이밍 × 방어템 종류 × 치유감소 필요 × 질풍 계열 필요)로 시나리오별 재랭킹, 가중 프로파일 설정 가능.

## 범위

| | |
|---|---|
| 챔피언 | 애쉬, 베인, 징크스, 카이사, 코르키, 이즈리얼, 코그모, 유나라 |
| 키스톤 | 치명적 속도, 집중 공격, 정복자 (+ 최후의 일격 / 커트 다운) |
| 아이템 | 현행 원딜 풀 — 윤 탈, 터미너스, 황혼과 새벽, 나보리, C44 등 (`adc_sim/data/items_data.py`가 스탯·가격의 단일 출처) |
| 데이터 | Community Dragon 커넥터 + DDragon / LoL Wiki / Meraki 수동 교차검증 |

## 실행

Python 3.10 필요. 의존성은 matplotlib 하나입니다.

```bash
python3.10 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

# 챔피언별 빌드 랭킹 (끝에 matplotlib 창이 뜸)
.venv/bin/python -m adc_sim.simulations.vayne
.venv/bin/python -m adc_sim.simulations.ashe

# 챔피언 간 파워 비교
.venv/bin/python -m adc_sim.simulations.power_compare

# 케이스 기반 랭킹, 표만 출력(헤드리스 안전), 케이스 필터 옵션
.venv/bin/python -m adc_sim.simulations.case_ranking "def@4/nohc"
```

풀 랭킹 실행은 수 분 걸립니다. 케이스 필터 토큰은 케이스 축에 대응합니다: `def@4`=방어템 4번째 구매, `nohc`=치유감소 불요, `zealfree`=질풍 계열 제약 없음 등. 헤드리스/자동화 환경은 `MPLBACKEND=Agg`를 앞에 붙이면 블로킹 그래프 창이 안 뜹니다. CSV/JSON 리포트는 기본 꺼짐 — `adc_sim/settings.py`의 `result_export_enabled`로 켭니다.

## 구조

```text
adc_sim/
  engine.py        # 이벤트 루프 + 경감 계산
  champion.py      # 데미지 모델, 챔피언 킷(이벤트 기반 스킬, 마나)
  items.py         # 아이템 동작 클래스(온힛, 주문검, 증폭 훅)
  runes.py         # 키스톤 + 보조(적응형 온힛 분배)
  data/
    items_data.py      # 아이템 스탯/가격 — 단일 출처
    items_registry.py  # 키 → 설정된 아이템 인스턴스
    cdragon.py         # Community Dragon 커넥터(패치 대조용)
  simulations/     # 챔피언별 빌드 탐색 + 랭킹 + 리포트
tests/             # 70+ 유닛·회귀 테스트
```

## 패치마다 하는 일

1. 패치노트 대조; CDragon 커넥터로 raw 데이터 수집, DDragon/Wiki와 교차검증 (완전한 소스는 없음 — 특히 스킬 계수).
2. `items_data.py`/챔피언 서브클래스 갱신. 새 메커니즘은 동작 클래스 + 검증 불가 시 명시적 가설 태그(`[Hypothesis]`, `H-VAYNE-W` 등).
3. 랭킹 재실행; DPS 회귀 스냅샷(`tests/_baseline_dps.json` + `test_regression_diff`)이 의도치 않은 수치 변동을 잡아냅니다.

## 모델 한계 (먼저 읽어주세요)

이건 **이론 모델이지 실측 게임 데이터가 아닙니다**. 랭킹은 명시된 가정 하에서의 최선 추정치입니다:

- 단일 대상 허수아비: 이동, 사거리 차이, 포지셔닝 리스크, CC, 실드, 팀 맥락 없음.
- 사거리와 무관하게 공격 가동률 100% 가정 — 카이팅/모션 손실 없음. 짧은 사거리 챔피언(베인, 코그모)에게 유리하게 작용합니다. 코어별 타깃 방어력/마저는 시뮬 모듈의 `CORE_TARGET_STATS`에 고정 정의.
- 지속 DPS 측정; 유틸리티와 버스트 순간의 가치는 범위 밖.
- 일부 챔피언 강점은 의도적으로 미모델이라 낮게 나옵니다 — 징크스의 신남! 리셋/로켓 AoE, 베인의 선고 등. 이 도구는 *평타 DPS 수학*을 말해주지 "누가 게임을 이기는가"를 말해주지 않습니다.
- 데이터로 검증 불가능한 상호작용은 가설 태그와 함께 배포 — 지적 환영, 대부분 한 줄 데이터 수정으로 반영됩니다.

```bash

.venv/bin/python -m pytest tests/ -q
```

메커니즘별 유닛 테스트(은화살 배치, 구인수 proc 수학, 마나 게이팅, 적응형 룬 분배 등) + 의도치 않은 모델 드리프트를 잡는 챔피언 교차 DPS 회귀 스냅샷.

## 라이선스

**미정** — 라이선스를 결정 중이며(관대형 vs 비상업형) 곧 추가됩니다. 그 전까지 코드는 열람·리뷰용으로 공개되며 재사용에는 허가가 필요합니다. 질문·정정·가정 반박은 그와 무관하게 이슈로 환영합니다.
